## Publication controls and remaining boundaries

- Verify the release PR's final `main` tree matches this checked candidate before packing, and only tag that clean `main` commit.
- Publish the inspected exact 0.3.2 tarball locally under the authenticated package owner, then push the matching tag. The existing release workflow's published-version guard prevents a second npm publication.
- Local publication cannot supply GitHub OIDC build provenance. Do not claim it, fabricate an attestation, or relax npm authentication. Verify registry integrity matches the local tarball afterward.
- If a published problem is discovered, do not overwrite a version or move its tag. Prefer a corrective patch. Any package deprecation requires an explicit maintainer decision.
- The original skill evaluation's fresh-agent-per-phase and instruction-based-isolation limitations still apply. Actual Claude Code loading and human hearing remain outside the automated evidence.
- Record final PR URLs, merge commits, npm integrity/version checks, tag, GitHub release, and any hosted CI override in the PR/release follow-up. Those remote actions are not represented as already complete by this preflight document.
