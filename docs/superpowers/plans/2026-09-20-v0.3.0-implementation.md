## Task 1: Bounded Debounce Buffer

**Files:** `src/adapter.ts`, new `src/changes.ts`, `__tests__/changes.test.ts`, and middleware/subscriber regression tests under `packages/zusound/`.

**Interface:** An internal buffer exposes `add(changes: Change[]): void`, `flush(): Change[]`, `clear(): void`, and a testable size. It is not exported from the package entry.

- [ ] Add a failing test for bounded retention and last-occurrence ordering:

```typescript
const buffer = createChangeBuffer()
const change = (path: string, newValue: number): Change => ({
  path,
  newValue,
  oldValue: newValue - 1,
  operation: 'update',
  valueType: 'number',
})
for (let value = 1; value <= 10_000; value++) buffer.add([change('count', value)])
expect(buffer.size).toBe(1)
buffer.add([change('status', 1), change('count', 10_001)])
expect(buffer.flush().map(({ path }) => path)).toEqual(['status', 'count'])
expect(buffer.size).toBe(0)
```

- [ ] Run `pnpm -C packages/zusound test -- __tests__/changes.test.ts` and record the missing-interface failure.
- [ ] Implement a `Map<string, Change>`. On each addition delete the old key before setting it, preserving last-occurrence order. Flush snapshots values and clears the map.
- [ ] Replace both append-only buffers in `adapter.ts` with this utility. Keep the same trailing-edge timer reset and descriptor semantics, including no-change callback behavior.
- [ ] Add fake-timer middleware/subscriber tests for repeated updates, multiple paths, final descriptor values, cleanup before flush, and terminal cleanup. Ensure teardown clears pending changes and does not emit.
- [ ] Run focused tests, package typecheck, and lint. Commit only runtime-owned changes with an appropriate focused message.

## Task 3: Typed Middleware Composition and Lifecycle

**Files:** `src/types.ts`, `src/adapter.ts`, `src/index.ts`, `__tests__/middleware.test.ts`, and `__tests__/middleware-types.ts`.

**Interfaces:** Keep `ZusoundInstance` callable in both modes. Its middleware overload preserves Zustand mutator tuples and adds the store's existing `zusoundCleanup` through a namespaced `StoreMutators` augmentation. Keep the old explicitly annotated initializer compatibility covered.

- [ ] Write strict TypeScript fixtures before changing signatures:

```typescript
import { createStore, type StateCreator } from 'zustand/vanilla'
import { devtools, persist, subscribeWithSelector } from 'zustand/middleware'
import { zusound } from '../src/index'
type State = { count: number; inc: () => void }
const state: StateCreator<State, [], []> = (set) => ({
  count: 0,
  inc: () => set((s) => ({ count: s.count + 1 })),
})
const plain = createStore<State>()(zusound(state, { enabled: false }))
plain.zusoundCleanup()
const selected = createStore<State>()(subscribeWithSelector(zusound(state)))
selected.subscribe(
  (s) => s.count,
  (count) => {
    const n: number = count
    void n
  }
)
selected.zusoundCleanup()
const persisted = createStore<State>()(devtools(persist(zusound(state), { name: 'counter' })))
persisted.persist.clearStorage()
persisted.zusoundCleanup()
// @ts-expect-error invalid state update must remain rejected
plain.setState({ count: 'invalid' })
```

- [ ] Run package typecheck, confirming missing cleanup/composition inference failures.
- [ ] Implement generic mutator-preserving signatures and a narrow typed implementation boundary. Avoid broad `any` propagation into public declarations. Preserve inference for the existing unannotated initializer form and the existing consumer `StateCreator<State, [], []>` assignment.
- [ ] Remove cleanup casts from runtime tests. Add runtime tests for the exact documented compositions, named devtools actions where supported, persist initialization, subscription selection, and separate stores using one middleware factory.
- [ ] Test idempotent cleanup, async-resume cancellation, unsubscribe plus subscriber cleanup, and reattachment through a fresh instance.
- [ ] Run package lint/typecheck/tests/build. Review generated `.d.ts` and `.d.cts`. Commit.
